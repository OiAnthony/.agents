# tech-blog：技术博客、工程博客、发布文章

适用：已经做完或做到一个阶段，向团队外的工程师讲做了什么、怎么做的、学到了什么。
要评审、要拍板的方案走 design-doc。

## 1. 先选骨架

| 文章类型 | 适用场景 | 骨架 |
|---|---|---|
| 探索型：提出一个概念或系统 | 方向未定，需要解释边界并用证据验证 | A |
| 实践型：我们做了什么、学到了什么 | 已完成一次实现，需要复盘过程 | B |
| 发布型或研究型：新产品、新方法、带评测 | 需要报告方法、结果和局限 | C |

骨架模板：`assets/tech-blog-skeleton.md`。
标杆工程博客的结构规律见 `references/benchmarks.md`，需要对照质量基准时按需加载。


先看读者要判断什么，再选骨架：只有需要提出新概念、解释模块边界并用实验验证时才用 A；已经完成一次实现并复盘过程用 B；发布产品或报告评测结果用 C。不要因为文章主题是 Agent 或 Harness 就强行套 A。

### 骨架 A：探索型

1. **声明**（可选）：这是探索，不是产品承诺；哪些是原型。
2. **引子四步**：趋势一句 → 缺口（具体到数字：「一个人同时盯 3–5 个会话就到上限」）→ 给缺口起名 → 列出这个概念的 3–5 条可检验特征。
3. **模块地图**：把系统拆成几个模块，每个模块对应后文一节，配一张总图，图里的编号对应节号。只有材料明确给出模块职责时，才把职责写成事实；否则只写已观察到的边界和行为，并把解释标为推断或待验证。
4. **每个模块一节**：节标题是判断句；按「张力的两个代价 → 取舍 → 机制 → 证据 → 剩余代价」展开，借用的概念（如操作系统调度、数据库 WAL）当场映射到本系统。映射是解释工具，不得替代缺失的实现证据。
5. **和相邻概念的区别**：读者会联想到的已有方案，说清楚相同点和不同点。
6. **实验**：负载、对照、指标、消融，见第 3 节清单。
7. **开放问题**：分条，每条写清楚为什么难、目前的猜想。
8. **现状和指针**：原型在哪、做到哪一步、致谢。

### 骨架 B：实践型

1. 一段话：我们要做什么，遇到了什么问题，结论是什么。
2. 起点：最朴素的做法和它为什么不够（给失败的具体表现）。
3. 迭代：按时间或按问题，每一步写「观察 → 改动 → 效果」。
4. 现在的设计：一张图 + 关键机制。
5. 学到的东西：可迁移到读者项目里的几条，每条有本文中的证据。
6. 还没解决的问题。

### 骨架 C：发布型或研究型

1. 结论先行：发布了什么，关键数字。
2. 为什么要做：用户或研究上的问题。
3. 方法：怎么做的，足够让同行判断可信度。
4. 评测：基准、对照、方法论（数据集、指标定义、跑了几次、置信区间或方差）。
5. 局限：评测没覆盖什么，已知失败场景。
6. 怎么用 / 怎么复现。

## 2. 开头

- 第一屏回答：这篇讲什么问题、结论是什么、读者为什么该关心。
- 用具体场景或数字开场，不用宏大背景。
- 开头最后写。

## 3. 实验清单

- [ ] 负载：描述到能复现（数据规模、请求数、并发、硬件或模型版本）。
- [ ] 对照：和什么比？对照组配置公平吗？
- [ ] 指标：定义清楚（p50/p95 是什么的分位数？时间从哪算到哪？）。
- [ ] 次数：跑了几次，给方差或区间；只跑一次就写明。
- [ ] 消融：每个改动单独贡献了多少。
- [ ] 成本：时间、token、钱，任何读者会关心的代价。
- [ ] 反例：哪些场景变差了。
- [ ] 实测、推算和引用分开；写明结论适用的负载与尚未覆盖的范围。
- [ ] 如果基线失败，解释失败原因，不把失败直接当成方案收益。

## 4. 诚实的现状句式

- 「这是原型，在内部 X 个项目上跑了 Y 周。」
- 「这个数字只在 Z 负载下成立；更大规模我们还没测。」
- 「我们试过 A，没有用，原因是……」
 
现状至少拆成三件事：代码是否实现、是否默认启用、在哪种负载上验证过。只写「已支持」会把实现状态误读成普遍有效。

## 5. 不要学

- 品牌叙事和愿景段落（「我们相信未来……」）。
- 标杆的长句：只学结构，不学句长；长句如果承担多个判断就拆开。
- 没有数字的程度词（「大幅」「明显」之类）。
- 结尾升华。最后一节写开放问题或下一步就结束。

## 6. 检查清单

- [ ] 第一屏有结论和关键数字。
- [ ] 每个节标题是判断句。
- [ ] 总图编号和章节一一对应。
- [ ] 每个权衡写了两边的代价。
- [ ] 实验清单全部覆盖，或写明为什么没做。
- [ ] 有开放问题或局限一节。
- [ ] 去AI味扫描无 HIGH。
- [ ] 复杂图表、截图或配图有明确论证用途，不用装饰性图片填空。
