# api-doc：接口文档、API 参考、错误码

适用：读者要调用你的接口。他会搜索、跳读、复制粘贴，很少从头读。

## 1. 原则

- **单一事实源**：OpenAPI（或 protobuf、GraphQL schema）是事实源，参考文档从它生成或与它校验；手写文档只补充 schema 写不出的东西（为什么、什么时候用、陷阱）。
- **参考和指南分开**（Diátaxis）：参考文档只写事实，查得到、无叙事；「怎么完成一个任务」写成 howto，链接过去。
- **例子能直接跑**：curl 带完整 URL、必需 header、真实感的数据；返回示例和 schema 一致。
- 示例中的凭证使用环境变量或明确的假值；不贴真实 token、Cookie、个人数据或可执行的破坏性请求。
- **写清楚边界**：限制、默认值、错误，比 happy path 更重要。

## 2. 整份 API 文档的结构

1. 概述：这组接口做什么、Base URL、环境。
2. 鉴权：怎么拿凭证、放在哪里、过期和刷新。
3. 通用约定：请求格式、时间格式（RFC 3339，带时区）、ID 格式、分页、幂等、限流、版本、错误格式。
4. 资源和端点：按资源分组，每个端点一节（模板见 `assets/api-endpoint.md`）。
5. 错误码总表。
6. 变更日志：日期、变更、是否破坏兼容、迁移方法。

## 3. 单个端点要写

| 项 | 内容 |
|---|---|
| 标题 | `METHOD /path`，下面一句话说它做什么 |
| 何时用 | 和相近端点的区别（可选） |
| 权限 | 需要的 scope 或角色 |
| 路径参数、查询参数、请求体 | 表格：字段、类型、必填、默认值、约束（长度、范围、格式、枚举）、说明 |
| 请求示例 | curl |
| 响应 | 状态码 + 响应体 schema 表 + 示例 |
| 错误 | 这个端点特有的错误：状态码、`type`、触发条件、调用方该怎么做 |
| 副作用 | 发消息、扣费、发邮件、触发 webhook |
| 幂等和重试 | 能不能安全重试；幂等键 |

字段说明写「是什么 + 约束 + 例子」，不写「用户 ID」这种复述字段名的话：
`user_id` string，必填。下单用户的 ID，格式 `usr_` + 16 位 base62，例如 `usr_8fK2mQ0aZx91LpT3`。

## 4. 错误格式：RFC 9457 Problem Details

推荐用 `application/problem+json`（RFC 9457，取代 RFC 7807）：

```json
{
  "type": "https://api.example.com/problems/insufficient-balance",
  "title": "余额不足",
  "status": 422,
  "detail": "账户余额 30.00，本次需要 45.00。",
  "instance": "/v1/orders/ord_123",
  "errors": [
    { "pointer": "/amount", "detail": "超过可用余额" }
  ]
}
```

- `type` 是稳定的 URI，可以打开看说明；客户端按 `type` 分支，不按 `title` 文案。
- `title` 对同一 `type` 不变；`detail` 针对这次请求。
- 字段级校验错误用扩展字段（如 `errors`），用 JSON Pointer 指向出错字段。
- 文档里为每个 `type` 写：含义、触发条件、调用方怎么处理（重试？改参数？联系支持？）。

## 5. 通用约定逐项写清

- **分页**：游标还是偏移？参数名、默认和最大页大小、结束条件、排序是否稳定。
- **幂等**：哪些端点支持 `Idempotency-Key`；保留多久；相同 key 不同 body 返回什么。
- **限流**：额度、窗口、按什么维度；超限返回 429 和 `Retry-After`；相关响应头。
- **版本**：URL 版本还是 header；什么算破坏性变更；废弃流程（`Deprecation`、`Sunset` 头，提前多久通知）。
- **时间和金额**：时区；金额用最小货币单位整数还是 decimal 字符串。
- **空值**：字段缺失、`null`、空字符串分别表示什么。

## 6. 检查清单

- [ ] 每个端点都有能直接运行的请求示例。
- [ ] 每个字段写了类型、必填、约束；枚举列全了值。
- [ ] 每个端点列了特有错误和处理方式。
- [ ] 分页、幂等、限流、版本有统一说明。
- [ ] 示例和 OpenAPI 一致（最好由 CI 校验）。
- [ ] 破坏性变更在变更日志里有迁移说明。
- [ ] 没有叙事段落混进参考页；教程链接到 howto。
