## 1. AI 味从哪来

- **向均值回归**：模型倾向输出统计上最常见的词和结构。结果是具体事实被换成泛泛而谈的「重要性」，句长、段长、结构都趋于均匀（Wikipedia: Signs of AI writing）。
- **对话训练的残留**：开场白、收尾的「希望对你有帮助」、过度格式化（加粗标签、列表、表格）。
- **模型代际口癖**：每一代模型有自己的高频词和句式，而且会随版本变化（GPT-4 时代的 delve，GPT-6 时代的 foster / leverage / quietly）。所以词表要按模型维护，并定期用自己的产出更新。
- **没想清楚**：最根本的原因。作者没有具体判断和证据时，模型只能填充模板。这一条没有任何脚本能修，只能回到 `shared.md` 第 2 节补证据。

## 2. 三层诊断

| 层 | 看什么 | 例子 | 脚本能查吗 |
|---|---|---|---|
| 词汇 | 套话、黑话、程度词、模型口癖 | 赋能、至关重要、值得注意的是、delve | 能（patterns.yaml） |
| 句式 | 翻案、递进拔高、冒号揭晓、段尾复述、三连排比 | 不是 X，而是 Y；不仅……更是…… | 大部分能 |
| 篇章 | 句长和段长均匀、标签列表、标题过密、宏大开头、升华结尾、每段同构 | 每节都是「定义—意义—挑战—展望」 | 部分能（结构检查） |
| 内容 | 没有具体事实、无对照的数字、虚假范围、替读者定义身份 | 「在各种场景下显著提升效率」 | 不能，要人判断 |

判断原则（参考 humanizer、write 的做法）：
- 一处翻案腔、一处收尾升华，单独出现就值得改。
- 一个「重要」「显著」不算问题，三五处聚集才是。
- 看密度，不看单个词。脚本的 `escalate_at` 就是这个意思。

## 3. 模型画像

### gpt-6.1-sol

依据：OpenAI《Using GPT-6》提示指南的 slop 清单（官方，高可信）；Wikipedia「Signs of AI writing」GPT-6 时代词表（社区整理，中可信）。gpt-6.1-sol 是否完全继承 GPT-6 的口癖，未单独验证。

| 倾向 | 表现 | 扫描规则 |
|---|---|---|
| 过度格式化 | 默认给列表、表格、加粗标签 | S03、D05 |
| 标签冒号开头 | Bottom Line: / In short: / The simplest mental model is: ；中文「一句话：」「简而言之：」 | G01、G05 |
| 纠偏框架 | This isn't about X. It's about Y. / should be treated as … rather than；中文「应视为……而非」「并不意味着」 | G03、G07、Z10 |
| 自问自答 | Question? Answer. | G04 |
| 口癖词 | genuinely, foster, leverage, quietly, steady, dependable, multifaceted；中文「真正」「切实」「默默」 | G02、G08 |
| 声明没做什么 | 「其余保持不变」「我不会改动……」 | G06 |
| 跨会话重复短语 | 同一个比喻、同一个句式反复出现 | 用 `--ngrams` 在自己的产出上找 |
| 短句均匀 | 句子集中在 8–20 词，句号逗号多 | S01 |

### deepseek-flash

依据：用户在 r/DeepSeek 的反馈（个例，低可信）+ 中文写作中的常见观察（未经语料验证）。规则默认偏保守，建议用你自己的 20 篇以上产出跑 `--ngrams` 校准。

| 倾向 | 表现 | 扫描规则 |
|---|---|---|
| 推理外泄 | 正文里出现「等等，」「不对，」「让我再想想」「Wait,」 | D01、D02 |
| 冗长、不守字数 | 超出长度要求，结论反复重述 | 人工：对比字数要求；Z21 |
| 应答前缀 | 「好的，下面……」「根据你的要求，」 | D04 |
| 口播强调 | 说白了、一句话总结、划重点 | D03 |
| 中文套话 | 翻案腔、递进拔高、宏大开头、挑战展望收尾 | Z 系列 |

## 4. 风格模仿协议

比列禁用词更有效的做法：给模型一个具体的目标风格。

### 4.1 从样例提取风格卡

给 1–3 篇目标风格的文章（用户自己的旧文、标杆博客），先提取风格卡，再写。风格卡模板：`assets/style-contract.md`。提取项：

- 读者和人称（「我们」还是「我」，是否直接称呼读者）
- 句长分布（短句比例、最长句大约多长）
- 段落长度和段首句的写法
- 标题写法（判断句还是名词短语）
- 证据习惯（每个判断后跟什么：数字、代码、链接）
- 格式习惯（列表、表格、加粗的使用频率）
- 术语处理（中英混排规则）
- 3–5 句可代表风格的原句（只用来对齐语气，不抄内容）
- 这个作者从不做的事（例如从不用感叹号、从不在结尾总结）

### 4.2 写作提示骨架

正面描述要什么，比只列禁止项更有效；禁止项作为补充放在最后。提示的格式本身会影响输出格式：想要段落就用段落写提示，不要用一长串项目符号。

**gpt-6.1-sol**（它的倾向是过度格式化和标签式开头）：

```text
你在为〈读者〉写〈体裁〉。用连贯的段落写，每段围绕一个判断展开，判断后紧跟证据。
只有对比三项以上的数据时才用表格；推理过程不要拆成列表。
直接陈述结论，不要先说它不是什么。不要用「一句话：」「简而言之：」这类标签开头。
不要说明你没有改动或不会做什么。
风格参照下面的风格卡和例句，学语气和节奏，不要复用其中的内容。
〈风格卡〉
〈2–3 句例句〉
长度上限：〈N〉字。
```

**deepseek-flash**（它的倾向是冗长和推理外泄）：

```text
〈简洁的角色和任务，一两句〉
只输出最终正文，不要输出思考过程，不要开场白和结尾客套。
长度上限〈N〉字，超出就删掉重复的论述，不要压缩事实。
〈风格卡〉
正文从下面这一行开始：
# 〈标题〉
```

DeepSeek 相关的经验（来自检索综合，中低可信）：系统提示保持简短；用「正文从这里开始」这类输出锚点；不要加「一步一步思考」（推理模型自己会想，加了反而外泄）；需要时调低 reasoning effort。

### 4.3 模仿的边界

- 模仿风格，不复制内容和独特表达。
- 风格卡和事实冲突时，事实优先。
- 样例自己有 AI 味时，先扫一遍样例，别把它的口癖也学走。
- [ ] 样例只提供语气、节奏和格式证据；其中的数字、观点、架构和专有名词不自动成为当前文稿的事实。
- [ ] 参考样例与任务材料冲突时，保留任务材料的事实，并把冲突标为待核实，不用模仿来掩盖缺口。

## 5. 静态扫描

```bash
S=~/.agents/skills/write-docs/scripts/scan_ai_taste.py
python3 $S draft.md                          # 通用规则，HIGH 时退出码 1
python3 $S draft.md --profile gpt-6.1-sol    # 加 GPT-6 画像规则
python3 $S draft.md --profile deepseek-flash
python3 $S docs/ --profile all --fail-on medium
python3 $S outputs/ --ngrams 4 --top 40      # 在自己的模型产出里找重复口癖
```

详见 `scripts/README.md`。规则 id：Z 中文、E 英文、P 残留、G gpt-6.1-sol、D deepseek-flash、S 结构。

## 6. 改写循环

1. **扫描**：记下 HIGH 和聚集的 MEDIUM。
2. **分类**：每处问题是哪一种？
   - **可改写**：有实际内容，只是表达套路化。改说法。
   - **空心**：去掉套话后什么都不剩。直接删；如果这里本该有内容，回去补证据，不要换个说法继续空着。
3. **改写**：一次改一类问题。常用改法：
   - 翻案腔 → 直接陈述后半句。
   - 程度词 → 数字和对照，给不出就删。
   - 段尾总结 → 删；有新推论就单独成句。
   - 标签列表 → 段落或表格。
   - 宏大开头 → 第一句写具体问题。
   - 升华结尾 → 写开放问题或下一步，然后停。
4. **复扫**：最多三轮。三轮后还有 HIGH，问题在内容层，回到提纲。
5. **事实核对**：对比原稿，数字、名称、链接、代码、限定条件不能变。改写最容易丢的是限定条件（「在 X 负载下」）。

## 7. 防止矫枉过正

这些「去AI味」技巧会制造新的假：
- 故意加口语、语气词、网络用语（「说实话」「讲真」「绝了」）。
- 故意写错字、加不完美。
- 用金句收尾替代升华收尾，还是升华。
- 为了句长变化而硬拆长句、硬加短句。
- 同义词轮换（为避免重复把「会话」换成「对话」「Session」）。
- 删光所有过渡，段与段之间失去逻辑连接。

目标是准确和具体，不是「不像 AI」。

## 8. 个人口癖库

模型的口癖会随版本变化，通用词表会过时。维护你自己的：

1. 收集最近 20 篇以上由 gpt-6.1-sol 或 deepseek-flash 生成的文本。
2. `python3 $S corpus/ --ngrams 4 --top 60 --min-count 3`，看在多个文件里都出现的短语（第二列是文件数）。
3. 把确认是口癖的加进 `patterns.yaml`，放在对应 profile 下，severity 先设 low，加 `escalate_at`。
4. 作者自己的固定用语用 `--allow` 或 `--allow-file` 放行。

## 9. 局限

- 静态规则只能查到词汇和部分句式。篇章和内容层要人判断。
- AI 检测器和人工判断都不可靠（Wikipedia 指出人工识别接近随机）。不要把扫描分数当作「是否 AI 写的」的证据，它只是写作质量的提示。
- 规则有误报：「不是 X 而是 Y」在真实纠错时是正常用法。保留时说得出理由即可。
- deepseek-flash 的规则证据弱，需要用你自己的语料校准。
