# 把并发会话从 3 个提到 12 个后，p95 延迟反而降了一半

我们一个人同时盯 3 到 5 个 Agent 会话时，大部分时间花在切窗口和重读上下文上。上个月我们给内部的编排器加了一个路由层，把多个会话的请求合批发给模型。

改动有三处。路由器按 2.5 秒窗口合批，平均每批 2.8 个请求；单次调用从 2.5 秒变成 3.9 秒，但摊到每个请求只有 1.6 秒。第二处是共享前缀缓存，缓存 token 从 2323 万涨到 3177 万。第三处是失败重试改成只重放最后一步。

在 300 条消息、20 个请求的固定负载上跑 5 次，p50 是 12.4 分钟，p95 是 15.7 分钟。对照组的 p95 是 29.5 分钟。

这套做法有两个已知问题。合批窗口在低负载时会白等 2.5 秒；缓存命中依赖提示词前缀稳定，改一次系统提示就要重新预热。我们还没想好低负载时怎么自动缩窗口。

原型代码在 `harness/router` 目录，复现脚本是 `bench/run.sh`。
