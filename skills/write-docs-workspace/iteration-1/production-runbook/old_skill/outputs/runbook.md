# 生产环境 Runbook：`orders.queue_lag > 300s` P1 告警

## 1. 适用范围

| 项目 | 信息 |
|---|---|
| 告警 | `orders.queue_lag > 300s` |
| 严重级别 | P1 |
| 环境 | `prod-cn1` |
| 当前 `orders-api` 版本 | `v2.8.0` |
| 影响 | 订单确认延迟 |
| 可能相关因素 | 最近一次发布 |
| 需要观察的指标 | `queue_lag`、`consumer_error_rate` |

本 Runbook 仅适用于上述环境和版本信息。除 `queue_lag > 300s` 外，不增加其他监控阈值。

## 2. 处置原则

1. **先止血，再诊断。**
2. 只有在检查发布状态并确认最近一次发布与告警相关后，才执行 `orders-api` 回退。
3. 异步确认开关仅在需要临时关闭异步确认时使用。
4. 止血后持续观察 `queue_lag` 和 `consumer_error_rate`。
5. 每 15 分钟仍未缓解时，升级给订单值班群。

## 3. 前置条件

开始处置前确认：

- 当前告警对象是 `prod-cn1` 的 `orders.queue_lag > 300s` P1 告警。
- 已确认影响为订单确认延迟。
- 可以检查最近一次发布的状态及其与告警的相关性。
- 仅在确认发布相关后执行部署回退。
- 仅在确实需要暂时关闭异步确认时执行开关变更。
- 已准备记录每次操作的时间、执行人、结果和观察到的指标状态。

## 4. 止血步骤

### 4.1 检查最近一次发布状态

先检查 `orders-api` 最近一次发布状态，并确认它是否与本次告警相关。

- **预期结果：** 得到发布状态和相关性判断。
- **下一步：**
  - 如果确认相关，执行 [4.2 部署回退](#42-部署回退)。
  - 如果未确认相关，不要仅因本告警执行部署回退；按 [5. 诊断](#5-诊断) 继续。

### 4.2 部署回退

仅在 4.1 已确认最近一次发布与告警相关时执行：

```text
kubectl -n orders rollout undo deploy/orders-api --to-revision=41
```

- **预期结果：** `orders-api` 回退到 revision `41`。
- **执行后：** 立即观察 `queue_lag` 和 `consumer_error_rate`，并记录结果。
- **失败或无法确认结果时：** 记录失败信息，不要假定回退已生效；按 [6. 升级路径](#6-升级路径) 处理。

### 4.3 暂时关闭异步确认（可选）

如果仍需要止血，并且需要暂时关闭异步确认，执行：

```text
opsctl flag set orders.async_confirmation false --env prod-cn1
```

- **预期结果：** `prod-cn1` 中 `orders.async_confirmation` 被设置为 `false`。
- **执行后：** 观察并记录 `queue_lag` 和 `consumer_error_rate`。
- **限制：** 这是临时止血动作，不应替代后续诊断。

## 5. 诊断

完成止血动作后，再进行诊断：

1. 结合 4.1 的发布状态判断，确认最近一次发布是否可能导致本次告警。
2. 持续观察 `queue_lag`，确认是否仍满足 `> 300s` 的告警条件。
3. 观察 `consumer_error_rate`，记录其状态和变化；给定信息未提供该指标的额外阈值，不自行增加阈值。
4. 记录部署回退和/或异步确认开关变更后的指标结果。
5. 如果指标没有缓解，或无法确认止血动作已生效，按 [6. 升级路径](#6-升级路径) 处理。

## 6. 验证标准

满足以下记录要求后，才可认为本次处置已完成：

- `queue_lag` 不再满足 `> 300s` 的告警条件。
- 已观察并记录 `consumer_error_rate` 的结果；不使用未提供的额外阈值判断该指标。
- 已记录实际生效的止血动作：部署回退、异步确认开关变更，或未执行相关动作。
- 订单确认延迟的处置结果已记录。
- 若使用了临时异步确认关闭措施，已记录后续恢复安排。

## 7. 回退方式

### 7.1 部署回退动作

本 Runbook 提供的部署回退目标是 revision `41`。输入信息未提供从 revision `41` 恢复到其他版本的具体命令，因此不得自行补造恢复命令。若需要恢复原发布或其他版本，使用现有发布流程，并记录目标版本和结果。

### 7.2 异步确认开关

`orders.async_confirmation false` 是临时措施。措施不再需要时，应恢复该开关在事件前的状态，并记录恢复结果。给定信息未提供具体恢复命令或事件前状态，不在本 Runbook 中补造命令或状态。

## 8. 升级路径

- 如果每 15 分钟仍未缓解，升级给**订单值班群**。
- 升级信息至少包含：
  - 告警：`orders.queue_lag > 300s` P1；
  - 环境：`prod-cn1`；
  - 影响：订单确认延迟；
  - `orders-api` 当前版本：`v2.8.0`；
  - 最近一次发布的状态及是否确认相关；
  - 已执行的止血动作及预期结果；
  - `queue_lag` 和 `consumer_error_rate` 的最新观察结果；
  - 尚未缓解的持续时间和最近一次观察时间。
