# Runbook：`orders.queue_lag > 300s` 先止血再诊断

**含义**：`orders.queue_lag` 超过 `300s`，说明订单队列出现积压。

**影响**：订单确认延迟。

**紧急程度**：P1，立即处理。

**升级**：每隔 `15` 分钟仍未缓解，升级给订单值班群。

**适用范围**：环境为 `prod-cn1`；当前 `orders-api` 版本为 `v2.8.0`。最近一次发布可能与告警相关，需先检查发布状态。

## 前置条件

- 确认当前告警为 `orders.queue_lag > 300s`，目标环境为 `prod-cn1`。
- 确认当前 `orders-api` 版本为 `v2.8.0`。
- 具备检查发布状态以及执行下方生产变更命令的权限。具体权限要求未在材料中提供。
- 发布状态检查入口或命令未在材料中提供，不能自行补造。

## 1. 先止血

先检查最近一次发布是否与告警相关。只有确认相关后，才执行回滚。若仍需要暂时停止异步确认，再执行关闭开关的动作。

| 情况 | 操作 | 命令或入口 | 预期结果 | 回退方式 |
|---|---|---|---|---|
| 最近一次发布确认与告警相关 | 回滚 `orders-api` | `kubectl -n orders rollout undo deploy/orders-api --to-revision=41` | `orders-api` 回退到 revision `41`；随后观察 `queue_lag` 和 `consumer_error_rate` | 如需撤销本次回滚，恢复命令未在材料中提供。不要根据版本号自行推断 revision `41` 对应的版本。 |
| 仍需要暂时关闭异步确认 | 关闭 `orders.async_confirmation` | `opsctl flag set orders.async_confirmation false --env prod-cn1` | 异步确认开关被设置为 `false`；随后观察 `queue_lag` 和 `consumer_error_rate` | 将 `orders.async_confirmation` 恢复为开启状态；恢复命令未在材料中提供。 |

回滚和关闭开关都会改变生产行为。执行后不要只看命令是否返回成功，还要进入下方验证步骤观察两个指标和订单确认延迟。

## 2. 验证止血效果

1. 观察 `orders.queue_lag`。
   - 通过现有监控入口查看；监控链接或查询命令未在材料中提供。
   - 继续记录该指标，直到它不再满足 `> 300s` 的告警条件。
2. 观察 `consumer_error_rate`。
   - 记录变更后的指标状态。
   - 材料未提供该指标的恢复阈值，因此不能自行补充数值标准。
3. 检查订单确认延迟是否缓解。
   - 材料未提供该业务指标的具体验证入口或阈值。
   - 在这些信息补齐前，只能记录观察结果，不能据此填写“已恢复”。
4. 如果每隔 `15` 分钟仍未缓解，按“升级路径”处理，不等待额外的未提供阈值。

## 3. 诊断

止血动作执行后，再根据发布状态和指标变化判断原因：

| 线索 | 当前判断 | 下一步 |
|---|---|---|
| 最近一次发布 | 可能相关，尚未确认 | 检查发布状态；确认相关后回滚到 revision `41` |
| `orders.queue_lag` | 已触发 `> 300s` 告警 | 持续观察是否不再满足告警条件 |
| `consumer_error_rate` | 需要观察，恢复阈值未提供 | 记录变更前后的状态，不补造通过阈值 |
| 异步确认 | 可能需要暂时关闭，是否执行取决于现场判断 | 需要时执行 `opsctl` 命令，并记录开关状态 |

当前材料没有提供日志查询命令、监控链接、发布系统入口、`consumer_error_rate` 的阈值，也没有提供其他已确认原因。不要用未提供的信息扩展诊断结论。

## 4. 升级路径

每隔 `15` 分钟检查一次。如果仍未缓解，升级给订单值班群。升级内容至少包括：

- 告警：`orders.queue_lag > 300s`；
- 环境：`prod-cn1`；
- 当前版本：`orders-api v2.8.0`；
- 最近一次发布是否确认相关；
- 已执行的回滚或开关变更；
- `queue_lag`、`consumer_error_rate` 和订单确认延迟的观测结果。

订单值班群的具体名称、联系方式和升级消息模板未在材料中提供。

## 验证标准

满足以下条件后，才可记录为本次告警已缓解：

- `queue_lag` 不再满足 `> 300s` 的告警条件；
- 已观察并记录 `consumer_error_rate`；
- 订单确认延迟已得到现场确认；
- 若仍未满足上述条件，则继续按 `15` 分钟周期升级给订单值班群。

材料未提供 `consumer_error_rate` 和订单确认延迟的具体通过阈值。不得用自定义阈值替代现场确认。
